# LLM Compare

LLM Compare — приложение для сравнения ответов языковых моделей на один и тот же вопрос.

Выберите 2–4 модели и отправьте один вопрос всем одновременно. Ответы отображаются рядом с временем получения; на мобильном экране переключаются вкладками. Ошибку одной модели можно повторить отдельно.

Текущая версия работает в **демо-режиме** с четырьмя тестовыми моделями, без API-ключа и внешних запросов к языковым моделям. Каждый вопрос запускает отдельное сравнение, без истории диалога. Ответы выводятся обычным текстом, целиком после завершения всех попыток.

## Использование

- По умолчанию выбраны две разные модели. Кнопка «+» справа открывает поиск и добавление; максимум — четыре модели. При двух моделях удаление недоступно.
- Enter отправляет вопрос; Shift+Enter добавляет строку. Максимум — 16 КиБ UTF-8. Исходные пробелы и переносы сохраняются.
- Во время сравнения состав моделей фиксирован. Новый черновик можно редактировать, отправка доступна после завершения.
- «Повторить ответ» использует исходный вопрос только для выбранной неуспешной модели. Успешные колонки сохраняются. Автоматических повторов нет.
- Следующий вопрос заменяет текущее сравнение. «Новое сравнение» очищает ответы, сохраняя набор моделей и черновик. Перезагрузка страницы очищает текущее состояние.
- В демо-каталоге есть короткий, подробный и медленный ответы, а также модель с постоянной тестовой ошибкой. Её повтор снова возвращает ошибку — это ожидаемый сценарий для проверки восстановления интерфейса.

## Запуск

Требуются Node.js **24.19.0** и npm **11.17.0**. Все команды выполняются из корня репозитория.

```sh
npm ci
npm run dev
```

Интерфейс: http://127.0.0.1:5173. API: http://127.0.0.1:3001. Vite перенаправляет запросы `/api` на сервер.

Настройки необязательны. Для изменения адреса или порта сервера создайте `.env` в корне по образцу `.env.example`. Поддерживается только `LLM_MODE=mock`; другие значения останавливают запуск, без скрытой подмены режима. Значения `.env` не передаются клиенту.

## Проверка и сборка

```sh
npm run typecheck
npm test
npm run build
```

`npm run check` последовательно выполняет все три проверки. CI запускает ту же команду.

После сборки `npm start` запускает API. Для локального просмотра собранного интерфейса запустите `npm run preview -w @llm-compare/web` в другом терминале; API должен оставаться запущенным. Сервер API самостоятельно не раздаёт статические файлы интерфейса.

## Структура

- `apps/web` — React, TypeScript, Vite; собственные компоненты и CSS без UI-библиотек.
- `apps/server` — Fastify, конфигурация и тестовый адаптер с управляемыми задержками и ошибками.
- `packages/contracts` — общие Zod-схемы и типы публичных данных, без серверной конфигурации.
- `tests` — проверки API, параллельности и изоляции ошибок, конфигурации, выбора моделей, формы и повтора ответов.

## API

| Маршрут | Ответ |
| --- | --- |
| `GET /api/health` | `{ "status": "ok" }`, без обращения к адаптеру |
| `GET /api/models` | Версия протокола и каталога, режим, нормализованный список моделей |
| `POST /api/comparisons` | Один вопрос, 2–4 уникальных цели, отдельный результат каждой попытки |
| `POST /api/retries` | Повтор одной цели, отдельный результат попытки |

Тестовые модели помечены как демонстрационные. Тарифы неизвестны (`null`); потоковая генерация и reasoning не поддерживаются. Ошибка каталога возвращает HTTP 503 с безопасным кодом `CATALOG_UNAVAILABLE` и возможностью повторить загрузку вручную.

Запрос сравнения содержит `protocolVersion: 1`, UUID `conversationId`, `runId`, `turnId`, исходный `prompt` и массив `targets`. Каждая цель содержит UUID `columnId` и `attemptId`, `modelId` из каталога и пустой `history: []`. Для повтора вместо `targets` передаётся один объект `target`. Непустая история и неизвестные поля отклоняются.

Ответ содержит те же идентификаторы запуска и массив `results`: `columnId`, `attemptId`, `modelId`, `status`, `text`, `totalMs` и `error`. Статусы: `succeeded`, `failed`, `timed_out`, `cancelled`; `error` равен `null` только при успехе. Время измеряется на сервере отдельно для каждой попытки.

Таймаут попытки — 10 секунд, лимит ответа — 512 КиБ UTF-8, лимит HTTP-тела — 256 КиБ. При ошибке входа генерация не начинается. Повторный `runId` отклоняется с HTTP 409; защита хранится в памяти процесса пять минут после завершения. Общая ёмкость сервера — восемь одновременных попыток; при нехватке мест весь новый запуск отклоняется с HTTP 429. Эти ограничения относятся к локальному демо и не являются лимитами внешнего провайдера.
