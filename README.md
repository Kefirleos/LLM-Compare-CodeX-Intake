# LLM Compare

Задайте один вопрос сразу 2–4 языковым моделям и сравните их ответы. На компьютере ответы идут в соседних колонках, на телефоне между моделями можно переключаться вкладками.

Для первого знакомства есть деморежим без ключа. Чтобы получить ответы реальных моделей, подключите CodeX Proxy в режиме Live.

## Быстрый старт

Установите Node.js **24.19.0** и npm **11.17.0**. Если репозиторий уже скачан, перейдите в папку с `package.json` и выполните последние две команды.

```sh
git clone https://github.com/Kefirleos/LLM-Compare.git
cd LLM-Compare
npm ci
npm run dev
```

Команда `npm run dev` запускает интерфейс и сервер. Для обычного запуска откройте **LLM Compare** по адресу из первой строки таблицы.

| Что открывается | Адрес по умолчанию | Когда нужен |
| --- | --- | --- |
| **Интерфейс LLM Compare** | [http://127.0.0.1:5173/](http://127.0.0.1:5173/) | После `npm run dev`, в Демо и Live. |
| Локальное API | `http://127.0.0.1:3001/` | Для прямых запросов к серверу, например к `/api/health`. В интерфейсе запросы к API отправляются автоматически через `/api`. |
| Предпросмотр собранного интерфейса | [http://127.0.0.1:4173/](http://127.0.0.1:4173/) | При отдельном [запуске собранной версии](#запуск-собранной-версии). |

С настройками по умолчанию откроется режим **Демо**. Две модели уже выбраны. Введите вопрос и нажмите **«Сравнить»**. Попробуйте, например, «Объясни, когда нужен Redis, и приведи пример».

Чтобы проверить остановку ответа и повтор при ошибке, добавьте через **«+ Модели»** демонстрационные модели **«Медленный ответ»** и **«Ошибка»**. Тестовая модель с ошибкой при повторе снова покажет ошибку. По этому сценарию можно проверить, что остальные колонки сохраняют свои ответы.

## Режим Live

1. Получите действующий ключ CodeX Proxy. Если файла `.env` ещё нет, сделайте в корне проекта копию [`.env.example`](.env.example) с именем `.env`.
2. Укажите в `.env` режим Live и подставьте свой ключ вместо `replace_me`.

   ```dotenv
   LLM_MODE=live
   LLM_API_KEY=replace_me
   ```

3. Остановите предыдущий запуск через `Ctrl+C`, снова выполните `npm run dev` и обновите страницу приложения по адресу из [быстрого старта](#быстрый-старт). В шапке появится отметка **Live**, а в списке моделей — актуальный каталог CodeX Proxy. Если была открыта демобеседа, нажмите **«Новое сравнение»**, чтобы выбрать реальные модели.

В режиме Live браузер по-прежнему обращается к локальному API. Сервер передаёт вопрос и контекст соответствующей модели во внешний сервис CodeX Proxy. Каждый выбранный ответ и ручной повтор могут расходовать лимит ключа. Храните ключ в `.env`. Этот файл исключён из Git, а ключ используется только сервером.

Чтобы вернуться в деморежим, установите `LLM_MODE=mock` и перезапустите приложение.

## Как сравнивать ответы

- **Выберите модели.** На стартовом экране нажмите **«+ Модели»**. В сравнении на компьютере список открывается рядом с плюсом справа от ответов. На телефоне плюс расположен у вкладок, а крестик — рядом с названием открытой модели. Плюс появляется, когда можно добавить модель. Крестик доступен, пока моделей больше двух. После первого вопроса каталог можно обновить кнопкой **«Обновить модели»**.
- **Отправьте один вопрос всем.** Нажмите **«Сравнить»** или `Enter`. Для переноса строки используйте `Shift+Enter`. Ответы появляются по мере поступления и поддерживают Markdown, включая таблицы и блоки кода. Если сервис передал рассуждение, оно появится в отдельном блоке **Thinking**.
- **Остановите или повторите.** **«Остановить»** завершает поток в приложении и сохраняет полученный текст. Прекращение работы модели у провайдера зависит от сервиса. **«Повторить ответ»** запускает новую попытку только для выбранной модели с ошибкой в последнем вопросе.
- **Продолжите диалог.** Введите следующий вопрос в поле под ответами. Каждая модель получает свои предыдущие пары вопрос–ответ, завершившиеся успешно. Новая колонка начинает с пустой историей. Кнопка **«Новое сравнение»** открывает отдельную беседу.

## Как читать метрики

Нажмите **«Метрики»** под ответом нужной модели.

| Метрика | Что показывает |
| --- | --- |
| Общее время | Длительность попытки по часам сервера приложения, включая сетевое ожидание. |
| Первый фрагмент Thinking | Время до первого непустого фрагмента рассуждения. Строка появляется, если рассуждение пришло первым и время отличается от времени до текста ответа с учётом округления. Она также видна, если текст ответа так и не поступил. |
| Первый фрагмент ответа | Время до первой непустой порции текста ответа. |
| Входные и выходные токены | Счётчики из ответа API за эту попытку. Во вход могут входить предыдущие сообщения модели. |
| Оценка стоимости | Входные и выходные токены по стандартным ставкам каталога за миллион токенов. Ставки видны в подсказке. |

Если сервис не прислал счётчик или приложение не смогло измерить время, в соответствующей строке будет **«нет данных»**. Оценка стоимости выражена в USD и не учитывает скидки за кэш и специальные тарифы. Фактическое списание зависит от биллинга сервиса. Отметки скорости и стоимости сравнивают успешные ответы на один вопрос с доступными для сравнения значениями. [Схема CodeX Proxy](https://llm.codex.so/docs/json)

## Расширенные возможности

В проекте реализованы пять расширений из [задания CodeX](https://codex.so/llm-compare).

| Расширение | Что можно проверить |
| --- | --- |
| Стриминг | Ответы выводятся по словам в своих колонках. **«Остановить»** отменяет активные запросы приложения и оставляет полученный текст. |
| Метрики | Видны время до первого фрагмента, общее время, токены и оценка стоимости. Имеющиеся результаты сравниваются по скорости и стоимости. |
| Thinking | Когда прокси передаёт рассуждение, появляется анимированная строка и серый текст. Блок сворачивается перед ответом, его можно раскрыть повторно. |
| Форма ответа | Диалог продолжается через поле внизу. Поле растёт по мере ввода, проверяет размер вопроса и поддерживает отправку по `Enter`. Над формой появляется градиент, когда часть ответов остаётся ниже видимой области. |
| Инкрементальный Markdown | Ответ разбирается в AST по мере поступления. Обновляются затронутые блоки разметки. |

## История бесед

Кнопка **«История»** в шапке открывает сохранённые беседы. По умолчанию вопросы, ответы, метрики и черновики сохраняются в браузере. Чтобы вернуться к беседе, используйте тот же браузер и тот же адрес. У разных имён хоста (`localhost` и `127.0.0.1`) и портов отдельная история.

В панели истории можно отключить **«Сохранять на этом устройстве»**, удалить отдельную беседу или очистить всю историю. Отключение сохранения оставляет прежние записи доступными в списке.

## Если что-то пошло не так

| Что происходит | Что сделать |
| --- | --- |
| Порт занят | Проверьте по [таблице адресов](#быстрый-старт), какой части приложения нужен этот порт. Если уже запущена другая копия LLM Compare, остановите её через `Ctrl+C` в её терминале и повторите нужную команду запуска. |
| Live не загрузил список моделей | Проверьте `LLM_MODE` и ключ в `.env`, перезапустите приложение и убедитесь, что с компьютера доступен `llm.codex.so`. |
| Старая модель исчезла из каталога | Откройте **«Новое сравнение»** и выберите модели из обновлённого списка. Сохранённую беседу можно открыть для чтения из истории. |
| В длинной беседе достигнут лимит контекста | Начните новое сравнение. На одну модель допускается до 16 завершённых пар вопрос–ответ в пределах 64 КиБ контекста. |

## Для разработчика

| Команда | Что делает |
| --- | --- |
| `npm test` | Запускает тесты приложения и API. |
| `npm run build` | Собирает клиент, сервер и общие схемы. |
| `npm run check` | Запускает линтер, проверку типов, тесты, сборку и браузерные проверки. Полный вывод сохраняется в `check.log`. |
| `npm run check:live` | После сборки отправляет один короткий вопрос двум реальным моделям, чтобы проверить поток, ответы и отображение метрик. Требует ключ в `.env`. Эта проверка использует лимит ключа и запускается отдельно от CI. |

Для браузерных проверок нужен Chrome или Chromium. Если Playwright не находит браузер, выполните `npx playwright install chromium`. Хотите проверить другую пару в `check:live`? Укажите два ID через запятую в `LLM_COMPARE_LIVE_MODELS`.

### Запуск собранной версии

1. Соберите проект командой `npm run build`.
2. Запустите сервер командой `npm start`.
3. Во втором терминале выполните `npm run preview -w @llm-compare/web -- --port 4173 --strictPort` и откройте адрес предпросмотра из [таблицы адресов](#быстрый-старт).

### Структура проекта

- [`apps/web`](apps/web) — интерфейс на React и Vite, потоковый Markdown и история в IndexedDB.
- [`apps/server`](apps/server) — API на Fastify, каталог моделей и адаптеры демо и CodeX Proxy.
- [`packages/contracts`](packages/contracts) — общие типы и проверка данных.
- [`tests`](tests) — автоматические проверки, включая сценарии Playwright.

### Маршруты локального API

`GET /api/health` проверяет доступность сервера. `GET /api/models` возвращает каталог, а `?refresh=1` принудительно его обновляет. `POST /api/comparisons` отправляет вопрос выбранным моделям, а `POST /api/retries` повторяет одну попытку. С заголовком `Accept: application/x-ndjson` оба POST-маршрута возвращают поток событий. Форматы запросов и результатов описаны в [схемах API](packages/contracts/src/index.ts).
