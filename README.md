# LLM Compare

LLM Compare — приложение для сравнения ответов языковых моделей на один и тот же вопрос.

Выберите 2–4 модели и отправьте один вопрос всем одновременно. Ответы отображаются рядом с временем получения; на мобильном экране переключаются вкладками. Ошибку одной модели можно повторить отдельно.

По умолчанию включён **демо-режим** с четырьмя тестовыми моделями, без API-ключа и внешних запросов к языковым моделям. Также доступен серверный адаптер CodeX Proxy API. Каждый вопрос запускает отдельное сравнение, без истории диалога. Ответы отображаются в Markdown целиком после завершения всех попыток.

## Использование

- По умолчанию выбраны две разные модели. Кнопка «+» справа открывает поиск и добавление; максимум — четыре модели. При двух моделях удаление недоступно.
- Enter отправляет вопрос; Shift+Enter добавляет строку. Максимум — 16 КиБ UTF-8. Исходные пробелы и переносы сохраняются.
- Во время сравнения состав моделей фиксирован. Новый черновик можно редактировать, отправка доступна после завершения.
- «Повторить ответ» использует исходный вопрос только для выбранной неуспешной модели. Успешные колонки сохраняются. Автоматических повторов нет.
- Следующий вопрос заменяет текущее сравнение. «Новое сравнение» очищает ответы, сохраняя набор моделей и черновик. Перезагрузка страницы очищает текущее состояние.
- В демо-каталоге есть короткий, подробный и медленный ответы, а также модель с постоянной тестовой ошибкой. Её повтор снова возвращает ошибку — это ожидаемый сценарий для проверки восстановления интерфейса.
- «Обновить модели» запрашивает актуальный каталог, сохраняя ответы и выбранные колонки. Если модель исчезла, новое сравнение недоступно до явного сброса и замены недоступных моделей. Ошибка обновления сохраняет ответы и блокирует новые запросы до успешного обновления.

В режиме API названия и порядок моделей приходят с сервера провайдера. Предустановленных оценок скорости, точности, качества или цены нет. Время относится к конкретной попытке; стоимость и токены не вычисляются без достоверных данных API.

## Форматирование ответов

Поддерживаются заголовки, вложенные и нумерованные списки, выделение, цитаты, GFM-таблицы, код и безопасные ссылки. Блоки кода можно копировать; код не исполняется. Ссылки допускают HTTP/HTTPS и относительные адреса, открываются с защитой новой вкладки. Сырой HTML отключён, изображения заменяются текстовой пометкой без загрузки. Таблицы и код прокручиваются внутри колонки. Если форматирование не удалось, доступен исходный текст ответа.

## Запуск

Требуются Node.js **24.19.0** и npm **11.17.0**. Все команды выполняются из корня репозитория.

```sh
npm ci
npm run dev
```

Интерфейс: http://127.0.0.1:5173. API: http://127.0.0.1:3001. Vite перенаправляет запросы `/api` на сервер.

Настройки необязательны. Для изменения адреса или порта сервера создайте `.env` в корне по образцу `.env.example`. Поддерживаются `LLM_MODE=mock` и `LLM_MODE=live`, без скрытой подмены режима. Серверный ключ не передаётся клиенту; mock-режим его не читает.

## Подключение API

Для локального подключения CodeX Proxy API установите в серверном `.env`:

```dotenv
HOST=127.0.0.1
PORT=3001
LLM_MODE=live
LLM_API_KEY=replace_me
```

Замените `replace_me` своим действующим ключом сервиса; пустой ключ и это значение-заглушка останавливают запуск. Реальный `.env` исключён из Git. Получение ключа и доступный лимит определяются условиями провайдера. Отправка вопроса в live-режиме обращается к внешним моделям и может расходовать лимит аккаунта.

Адаптер использует фиксированный HTTPS-адрес `https://llm.codex.so`, серверный заголовок `x-api-key`, `GET /models` и `POST /generate` с полями `prompt` и `model`. Переадресации отключены. Базовый URL и заголовки нельзя изменить из браузера. Контракт описан в [публичной OpenAPI-схеме](https://llm.codex.so/docs/json).

Live-режим ограничен адресами loopback (`127.0.0.1`, `::1`, `localhost`); публичное размещение API в этой версии не поддерживается. Проверены контрактные сценарии на локальном HTTP-стенде, получение реального каталога и обычная генерация на `openai/gpt-5-mini`. Реальная генерация на остальных моделях, streaming, usage и стоимость пока не проверялись.

## Проверка и сборка

```sh
npm run typecheck
npm test
npm run build
```

`npm run check` последовательно выполняет все три проверки. CI запускает ту же команду.

После сборки `npm start` запускает API. Для локального просмотра собранного интерфейса запустите `npm run preview -w @llm-compare/web` в другом терминале; API должен оставаться запущенным. Сервер API самостоятельно не раздаёт статические файлы интерфейса.

## Структура

- `apps/web` — React, TypeScript, Vite, react-markdown и remark-gfm; собственные компоненты и CSS без UI-библиотек.
- `apps/server` — Fastify, конфигурация, каталог и адаптеры CodeX Proxy / demo.
- `packages/contracts` — общие Zod-схемы и типы публичных данных, без серверной конфигурации.
- `tests` — проверки API, параллельности и изоляции ошибок, конфигурации, выбора моделей, формы и повтора ответов.

## API

| Маршрут | Ответ |
| --- | --- |
| `GET /api/health` | `{ "status": "ok" }`, без обращения к адаптеру |
| `GET /api/models` | Версия протокола и каталога, режим, нормализованный список моделей |
| `POST /api/comparisons` | Один вопрос, 2–4 уникальных цели, отдельный результат каждой попытки |
| `POST /api/retries` | Повтор одной цели, отдельный результат попытки |

Тестовые модели помечены как демонстрационные. В live-каталоге используются имена из API и справочник провайдеров по известным префиксам ID; для неизвестного префикса отображается «Провайдер не указан». Тарифы неизвестны (`null`); потоковая генерация и reasoning пока не подключены. Их доступность для реальных моделей не предполагается автоматически.

Каталог кэшируется на 60 секунд, одновременные загрузки объединяются. `GET /api/models?refresh=1` принудительно обновляет каталог. Если обновить просроченный каталог не удалось, новый запуск отклоняется до генерации. HTTP 503 каталога содержит безопасный код `CATALOG_UNAVAILABLE` или нормализованную причину от адаптера; сырой ответ провайдера не передаётся клиенту.

Запрос сравнения содержит `protocolVersion: 1`, UUID `conversationId`, `runId`, `turnId`, исходный `prompt` и массив `targets`. Каждая цель содержит UUID `columnId` и `attemptId`, `modelId` из каталога и пустой `history: []`. Для повтора вместо `targets` передаётся один объект `target`. Непустая история и неизвестные поля отклоняются.

Ответ содержит те же идентификаторы запуска и массив `results`: `columnId`, `attemptId`, `modelId`, `status`, `text`, `totalMs` и `error`. Статусы: `succeeded`, `failed`, `timed_out`, `cancelled`; `error` равен `null` только при успехе. Время измеряется на сервере отдельно для каждой попытки.

Таймаут попытки — 10 секунд, лимит ответа — 512 КиБ UTF-8, лимит HTTP-тела — 256 КиБ. При ошибке входа генерация не начинается. Повторный `runId` отклоняется с HTTP 409; защита хранится в памяти процесса пять минут после завершения. Общая ёмкость сервера — восемь одновременных попыток; при нехватке мест весь новый запуск отклоняется с HTTP 429. Эти настройки приложения не являются лимитами внешнего провайдера. Прерывание локального соединения не гарантирует остановку вычислений и списания у провайдера.
